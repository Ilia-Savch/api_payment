# Контракт API

Пути без префикса `/api/v1`. Тела запросов и ответов — JSON.

## Маршруты

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| `GET /tariffs` | — | `200`: список `{id, title, price}` |
| `POST /payments` | `tariff_id`, `email`, `method`; необязательные `installment_months`, `promo_code`, заголовок `Idempotency-Key` | `201`: новый платёж; `200`: повтор по ключу; `404`: тариф не найден |
| `GET /payments/{id}` | ID платежа | `200`: платёж; `404`: платёж не найден |
| `GET /payments` | Необязательные фильтры `email`, `status` | `200`: список платежей; без совпадений — `[]` |
| `POST /webhooks/bank` | `payment_id`, `status`; заголовок `X-Signature` | `200 {"result":"ok"}`; `404`: платёж не найден; `409 {"error":"invalid_transition"}` |

Ошибки валидации — стандартный `422` FastAPI. Неверная или отсутствующая
подпись вебхука — `401 {"detail":"Invalid signature"}`.

Фильтры применяются через AND, email — точное совпадение. Без фильтров
возвращаются все платежи. Список упорядочен по возрастанию `id`.

## Поля платежа

`id`, `status`, `tariff_id`, `amount`, `discount`, `method`,
`installment_months`, `schedule`, `email`, `created_at`.

`amount` — сумма к оплате после скидки, `discount` — сумма скидки.
Обе суммы — целые копейки. `created_at` — дата и время с часовым поясом.
Без рассрочки `installment_months` и `schedule` равны `null`.
Ключ идемпотентности в ответ не входит.

## Правила платежей

- Тарифы по умолчанию: `basic=990000`, `standard=1990000`, `premium=2990000`.
  Цены берутся из конфигурации и обновляются при запуске без дублей;
  суммы уже созданных платежей не пересчитываются.
- Способы оплаты: `card`, `sbp`, `installment`. Для рассрочки обязателен срок
  3, 6 или 12 месяцев. Для остальных способов допустимый переданный срок
  приводится к `null`.
- `KVITTO10` даёт 10% скидки без учёта регистра. Неизвестный код — `422`.
  Скидка: `price * percent // 100`, итог: `price - discount`. Без кода скидка — 0.
- График содержит суммы в копейках, его сумма равна `amount`.
  Остаток идёт в первые платежи: `1990000 / 3 → [663334, 663333, 663333]`.
- Суммы, график и начальный статус `pending` задаёт сервер.
- Повторный `Idempotency-Key` с валидным телом возвращает прежний платёж с `200`,
  даже при изменённых параметрах. Уникальность ключа гарантирует PostgreSQL,
  в том числе при конкурентных запросах. Без ключа каждый запрос создаёт платёж.

## Банковский вебхук

Статусы: `pending`, `succeeded`, `failed`, `refunded`. Разрешены только
`pending → succeeded`, `pending → failed`, `succeeded → refunded`.
Любой другой переход, включая повтор статуса, — `409 {"error":"invalid_transition"}`
без изменения данных. Проверка и изменение атомарны, строка блокируется в транзакции.

`X-Signature` — HMAC-SHA256 исходных байтов тела с `WEBHOOK_SECRET`:
64 hex-символа без префикса. Подпись проверяется через `hmac.compare_digest`
до разбора JSON и обращения к БД; повтор заголовка отклоняется с `401`.
После расчёта подписи тело нельзя менять. Без непустого `WEBHOOK_SECRET`
приложение не запускается.
