# Работа с ИИ

Ассистент: Codex (GPT-6). Использованы PowerShell, Git, Python, `apply_patch`;
для чтения ТЗ на этапе планирования — pypdf, Poppler и просмотр страниц PDF.

## Ключевые запросы

1. Сначала изучить PDF, структуру и пример управления сессиями;
   составить план без написания кода. Отделить бизнес-логику от HTTP и CRUD,
   использовать PostgreSQL и Docker, не добавлять лишнюю логику.
2. Реализовать только первый этап: feature-ветку, каркас, зависимости,
   Ruff, mypy, pytest и проверочный список контракта. Использовать приложенный
   `config.py` как пример, сохранив маршруты без `/api/v1`.
3. Названия веток должны соответствовать смыслу изменений и заканчиваться
   на `-feature` или `-fix`.

## Найденные проблемы и принятые решения

- Первоначальное имя ветки не соответствовало уточнённому правилу именования.
  Ветку переименовали в project-scaffold-feature.
- Первый тест использовал TestClient; при запуске появилось предупреждение об устаревшем адаптере httpx.
  Тест перевели на httpx.AsyncClient с ASGITransport.
- Пример конфигурации содержал настройки других сервисов и префиксы /api и /v1.
  В каркасе оставили только необходимые настройки, а публичные пути сохранили по ТЗ.

## Проверки первого этапа

Перед коммитом выполнены Ruff, проверка форматирования, mypy, pytest и
`git diff --check`. Все проверки прошли; pytest — 6 тестов без предупреждений
на Python 3.12.10. Команды из `make check` запускались напрямую: GNU Make
в среде отсутствует. Платёжная логика и БД относятся к следующим этапам.
