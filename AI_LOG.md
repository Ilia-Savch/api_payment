# Работа с ИИ

Использовал Codex (GPT-6) для планирования, написания и проверки кода. Инструменты: PowerShell, Python, pypdf для чтения ТЗ, Git, Docker Compose, Ruff, mypy, pytest и httpx.

Ключевые запросы к ассистенту (сокращённо):

1. «Изучи PDF с ТЗ, составь поэтапный план без кода. Возьми структуру моего кода, отдельно вынеси бизнес-логику. Используй PostgreSQL и Docker, логи добавляй только в необходимых местах».
2. «Настрой отдельную сессию на запрос по примеру db_helper.py, commit/rollback оставь сервисам. Добавь модели, Alembic и начальные тарифы без дублей». Передал также config.py, docker-compose.yml и файлы настройки Alembic как примеры.
3. «Реализуй расчёты в целых копейках, идемпотентность и атомарные переходы статусов строго по ТЗ. Проверь конкурентные запросы». Отдельно согласовал HMAC-подпись вебхука и GitHub Actions.

Я задавал этапы, просматривал предложенный код и давал правки. Заметил жёстко заданные цены тарифов: попросил вынести их в конфигурацию и обеспечить обновление в БД. Предложил хранить несколько промокодов вместо одной константы; использовали словарь «код → процент». Обратил внимание на замечание линтера и предложил явно типизированный список изменений. Сам проверял API через curl: получил тарифы, создал платежи и прочитал их по ID.

Ошибки ИИ находились и проверками: в Compose различался приоритет настроек приложения и БД — заменили его единой явной подстановкой окружения. Тест читал ORM-объекты после rollback и закрытия сессии, вызывая DetachedInstanceError; чтение перенесли внутрь сессии.

Проверки выполнялись по ходу работы: Ruff, форматирование, mypy и 70 сценариев pytest с PostgreSQL прошли, включая гонки и отказы HMAC. Миграции проверены на чистой БД, команды README — в Git Bash. Workflow проверен;
