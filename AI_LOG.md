Работа с ИИ

Использовал Codex (GPT-6) для планирования, подготовки каркаса и настройки Docker Compose и PostgreSQL.

Ключевые запросы

Изучить ТЗ и существующие примеры, предложить план. Разделить HTTP-слой, бизнес-логику и доступ к БД; не добавлять функциональность вне задания.

Подготовить каркас, зависимости и проверки Ruff, mypy, pytest. Зафиксировать контракт API, сохранив маршруты без /api/v1.

Настроить Docker Compose, сессии PostgreSQL, две модели и Alembic. Цены тарифов вынести в конфигурацию и обновлять при запуске без дублей, сохраняя ID и суммы старых платежей. CRUD не должен выполнять commit.

Ошибка ИИ и исправление

В первом варианте Compose настройки приложения передавались через env_file, а PostgreSQL — через подстановку переменных. Проверка выявила различия в приоритете значений окружения. Оба сервиса переведены на одинаковую явную подстановку настроек.

Проверки и текущий результат

После второго этапа прошли Ruff, проверка форматирования, mypy, pip check, git diff --check, проверка конфигурации Compose и тестов. Тесты выполнялись на Python 3.12.10;

Образ собран, приложение и БД проходят healthcheck, /docs возвращает 200. Проверено сохранение данных PostgreSQL при пересоздании контейнера.

Этап 3: добавлены модели тарифов и платежей, Alembic и создание тарифов через ON CONFLICT. Миграция проверена на пустой БД и повторно; alembic check, Ruff, mypy и 7 тестов прошли. В новом тесте ИИ читал ORM-объекты после rollback и закрытия сессии: проверка падала с DetachedInstanceError; чтение перенесено внутрь сессии. Платёжная логика остаётся следующим этапом.

Цены перенесены в TariffsConfig и окружение. Синхронизация сохраняет ID тарифов и суммы платежей, логирует только изменения после commit. Ruff, mypy и 8 тестов на новой PostgreSQL прошли; проверены настройки окружения и запуск Compose. Новых ошибок бизнес-логики при проверке не обнаружено.

Этап 4: по запросу добавлены Pydantic-схемы и целочисленные расчёты скидки и рассрочки. По уточнению промокоды хранятся в словаре «код → процент»; добавление кода проверено тестами. Использованы Codex, PowerShell, Python, pypdf для сверки ТЗ и apply_patch. Ruff, форматирование, mypy, pip check и 43 теста с PostgreSQL прошли; стандартный 422 проверен через тестовый маршрут. Подтверждённых ошибок новой логики не обнаружено.

Этап 5: добавлены GET /tariffs и GET /payments/{id}. Через httpx и PostgreSQL проверены поля ответа, целые суммы, время с часовым поясом, null без рассрочки и 404, включая слишком большие ID. Ruff, форматирование, mypy и 50 тестов прошли. Подтверждённых ошибок новой логики не обнаружено.

По запросу добавлен бонус GET /payments с фильтрами email и status. Проверены отдельные фильтры, AND, пустой результат, 422 и сохранность данных. Ruff, форматирование, mypy и 53 теста с PostgreSQL прошли; ошибок новой логики не обнаружено.

Этап 6: добавлен POST /payments, серверный расчёт и идемпотентность через уникальный ключ PostgreSQL и ON CONFLICT. Добавлены 5 основных тестов (6 сценариев), включая синхронизированную гонку двух вставок и проверку одной записи в БД. mypy выявил возврат Any через scalar(); использован типизированный scalars().first(). Ruff, форматирование, mypy и все 59 сценариев с PostgreSQL прошли.
